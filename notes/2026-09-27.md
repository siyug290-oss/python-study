## 卡在哪

1. **看错了文档语言。** 在菜鸟教程搜 `count` 时进了 JavaScript 手册（`console.count()`）。
   网址里 `jsref` 是 JavaScript，`python3` 才是 Python。以后先看地址里那一段。

2. **变量名叫 `str`。** 它覆盖了 Python 的内置函数，一直没报错，但一旦写 `str(123)` 就崩：
   `TypeError: 'str' object is not callable`。
   **不要用内置名字当变量名**：`str` `int` `list` `dict` `sum` `len` `type` `input` `print`……

3. **`print(S.replace(" ",""))` 少了一层 `len()`。** 输出的是字符串本身，不是字符数量。
   `replace` 负责改造，`len` 负责数数，**两个动作要分开写**。

4. **`split(" ")` 和 `split()` 不是一回事。** 指定分隔符时，连续空格之间会产生空串：
   `"a  b  c".split(" ")` 得到 5 项（含两个空串），`"a  b  c".split()` 得到 3 项。
   **统计单词时用不带参数的 `split()`。**

5. **`encoding="uft-8"` 拼错了。** 字母顺序颠倒，报 `LookupError: unknown encoding: uft-8`。
   报错信息里直接写着拼错的那个词，很好定位。

6. **`print(f.read)` 忘了括号。** 打印出的是方法对象本身：
   `<built-in method read of _io.TextIOWrapper object at 0x...>`
   **名字后面跟了括号才是执行它。**

7. **`"w"` 会清空文件。** 在 `08_file.py` 第 3 步误用了 `w`，前两行被清掉了。
   追加必须用 `a`。这是我第一次亲眼看到 `w` 的破坏力。

## 一个更重要的发现

**修好代码 ≠ 修好数据。**

`notes_app.py` 改对之后，输出还是粘在一行——因为第一行是用**有 bug 的版本**写进去的旧数据。
程序改了，历史上已经产生的内容不会自动跟着变，需要单独处理。

真实工作里这种情况很常见：程序改好了，但数据库或文件里还留着旧格式的数据，得写迁移脚本。
