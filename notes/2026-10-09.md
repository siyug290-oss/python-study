## 卡在哪

1. **`input` 的类型问题，第三次踩。**

   ```python
   choice = int(input("请输入数字"))     # 转了 int
   if choice == "1":                    # 却和字符串比 → 永远 False
   ```

   同时 `t.remove(input(...))` 又**忘了转** —— 里面要做 `1 <= index <= len(...)`，
   字符串比不了。

   **一个该转没转，一个不该转却转了。**

   **判断标准**：这个值是拿去"比较文字"还是"做数学运算"？
   - 比较文字（菜单选项）→ **不转**
   - 数学运算（序号、金额）→ **转 int / float**

2. **直接运行测试文件，没有任何输出。**

   ```
   python test_models.py     →  （没有输出）退出码 0
   python -m pytest -v       →  正常显示结果
   ```

   原因：`test_models.py` 里只有**函数定义**，没有任何调用。
   **pytest 的工作就是"去找这些 `test_` 开头的函数并调用它们"。**

   **测试文件不是能直接跑的程序，它是"给 pytest 读的清单"。**

3. **找不到 pytest —— 虚拟环境导致的。**

   ```
   No module named pytest
   ```

   我把 pytest 装到了**系统 Python**，但 VS Code 的终端用的是
   `D:\code\python-study\.venv` 里的 Python。**这是两个不同的 Python。**

   而且 venv 的配置里有：

   ```
   include-system-site-packages = false
   ```

   **意思是"这个虚拟环境看不到系统里装的包"。**

4. `show()` 里写的是 `print(f"{i},{t}")`，输出 `1,买菜`。
   应该写 `{i}. {t}`，输出 `1. 买菜`（一个小标点，不影响功能）。

## 今天最重要的两个收获

### 一、测试能守住边界

四个测试里，有三个守的是"**不该发生的事**"：

| 测试 | 守什么 |
|---|---|
| `test_add_empty` | 加空白内容，数量不该变 |
| `test_remove_out_of_range` | 删第 99 条，数量不该变 |
| `test_remove_zero` | **删第 0 条，数量不该变** |

最后那个，**正是我前面在 `remove` 里写错的那个 bug**（`0 <= index` 会让
`pop(-1)` 删掉最后一条）。

以后谁再把 `1 <=` 改成 `0 <=`，**跑一次 pytest 四秒钟就会报红。**

**这就是测试的真正价值——不是证明代码对，是让你敢改代码。**

### 二、虚拟环境

**一个"项目专属的、独立的 Python"。**

我机器上现在有三个 Python：

- 系统 3.14（最初装 pytest 的地方）
- 系统 3.11
- **`.venv` 里的 3.14**（VS Code 自动建的，终端默认用这个）

**为什么要这样**：不同项目需要不同版本的包。项目 A 要 pytest 8、项目 B 要 pytest 9，
都装在系统里就会打架。**每个项目一个 venv，各装各的。**

**两个好处**：

1. venv 是"项目的一部分"，可以随手删掉重建，不影响系统
2. 别人拿到项目能还原出一模一样的环境（靠 `requirements.txt`）

**怎么判断自己在哪个 Python 里**：

- 看终端提示符有没有 `(.venv)`
- 或者敲 `python -c "import sys; print(sys.executable)"` 看完整路径

**装包要装进你正在用的那个 Python。** 在 VS Code 终端里敲
`python -m pip install xxx`，就会装进 venv。

**一个意外的好运**：10/2 顺手加到 `.gitignore` 里的那行 `.venv/`，
今天派上用场了——**虚拟环境有几百 MB，而且包含机器专属路径，绝不能提交。**
