## 今天学了

- **JSON 读写**（复习）：`json.dump` / `json.load`，`ensure_ascii=False` 让中文可读

- **自动持久化**：`__init__` 里自动 `load()`，`add()` / `remove()` 成功后自动 `save()`

## 卡在哪

1. **`self.load(self, filename="todo.json")` —— 多传了一个 self。**

   ```
   TypeError: TodoList.load() got multiple values for argument 'filename'
   ```

   一直没真正理解 `self`，所以不知道"调用时不用传"。

2. **`self` 到底是什么 —— 后面用这个等式才想通：**

   ```
   d1.bark()       等价于   Dog2.bark(d1)
   ```

   **`self` 就是个普通的第一参数**，用点号调用时 Python 自动帮你填。
   定义方法时要写（方法体里要用它），调用时不要写（Python 自动填）。

3. **`__init__` 只改了一半。**

   ```python
   def __init__(self):              # ← 参数没加
       self.filename = filename     # ← 右边改了，但 filename 没有来源
   ```

   **记住这个模式：要"接收一个值并存起来"，永远是两处**——
   括号里加参数，方法体里赋值。少一处都不行。

4. **文件夹被改名成 `2026-10-05---10-10`。**

   Git 不知道这是"改名"，显示成"删了旧文件夹 + 加了新文件夹"——
   **历史会断开**。已经改回去了。

5. **`python-study/todo.json` 出现在上一级目录。**

   **原因：相对路径是相对于"你敲命令时所在的文件夹"，不是"脚本所在的文件夹"。**

   `open("todo.json", "w")` 里的 `todo.json` 意思是"在当前位置创建"。
   所以从 `python-study` 里运行脚本，文件就建在 `python-study`。

   **脚本在哪 ≠ 运行时在哪。**

6. **加了持久化之后，四个测试全红了 —— 这是今天最有价值的一条。**

   ```
   FAILED test_add - assert 4 == 1
   FAILED test_add_empty - assert 4 == 0
   FAILED test_remove_out_of_range - assert 5 == 1
   FAILED test_remove_zero - assert 6 == 1
   ```

   **原因**：`__init__` 现在自动 `load()`，所以 `TodoList()` 不再是空的，
   而测试还按旧的理解在断言。

   **更严重的是数字在递增（4 → 4 → 5 → 6）** —— 说明
   **测试之间在互相污染**：所有测试共用同一个 `todo.json`，
   第一个写进去的数据被第二个读到，又写一遍……

   **这违反了"测试之间不该互相影响"这条纪律。**

   **持久化天生会带来"状态共享"，而状态共享会破坏隔离。**

   **修法**：pytest 的 `tmp_path` —— 在测试函数参数里写 `tmp_path`，
   pytest 会自动传一个**全新的空文件夹**进来。

   ```python
   def test_add(tmp_path):
       t = TodoList(tmp_path / "todo.json")
   ```

   顺便做了个重构：让类记住 `self.filename`，
   这样文件名只有一处来源（之前 `load` 和 `save` 各写了一遍默认值，是隐患）。

7. **类型注解写错了一处**：`remove(self, index: str)` 应该是 `int`。

   因为方法体里做的是 `1 <= index <= len(...)` 和 `index - 1`——**数学运算**。

   这个错误正好说明注解的价值：**打开类型检查后，它会帮你发现
   "声明和实现不一致"。**

8. **"注解没生效" —— 因为 Pylance 的类型检查默认是关的。**

   设置项 `python.analysis.typeCheckingMode` 默认值是 `off`。
   改成 `basic` 之后，传错类型才会画波浪线。

9. **找不到 `count` 方法** —— 它被十几行连续空行埋到文件最下面了。
   **空行不要留太多**，一个方法结束到下一个方法开始，空一行就够。

## 今天最重要的三个收获

### 一、`self` 的本质

```
d1.bark()   ==   Dog2.bark(d1)
```

**`self` 不是魔法，就是个普通的第一参数**，只不过用 `.` 调用时 Python 自动填。

### 二、持久化会破坏测试的隔离性

数据和代码不一样：**代码是只读的，数据是可变的**。
一旦测试开始读写真实数据文件，测试之间就会互相影响。

**`tmp_path` 就是标准解法**——每个测试一个独立的环境。

### 三、类型注解是"数据"，不是"注释"

用 `inspect.signature()` 能把注解读出来：

```
remove -> (self, index: int) -> None
count  -> (self) -> int
```

**注解存在函数对象里，所以工具能读到它。** 这就是为什么 Pylance 能检查。

而且**注解不强制检查**——传 `123` 给 `content: str`，程序照样跑。
它的价值在于：编辑器提示、给人看、配合静态检查工具。
