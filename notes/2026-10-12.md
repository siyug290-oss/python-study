## 卡在哪

1. **`uvicorn api:app` 报 `Could not import module "api"`。**

   又是**目录不对**——`api:app` 里的 `api` 是模块名，uvicorn 在**当前目录**里找。

   **这是第二次踩同一个坑**（10/10 那次是 `try_save.py` 找不到）。

   **养成动作：跑之前先看提示符里的路径。**

2. **uvicorn 进程卡死了**——端口占着，但请求超时没响应。

   处理办法：找到那个 PID，结束进程，重启。

   **这不是代码问题**，是 `--reload` 在 Windows 上偶尔会卡。

3. **`api.py` 我看不懂** —— 视频也看不清楚。

   最后用"**两个阶段**"讲通了（见下面）。

4. **接口返回空列表，但 `todo.json` 里明明有数据。**

   **原因**：`t = TodoList()` 是在**启动服务器的时候**执行的。
   那一刻 `todo.json` 还不存在，所以 `t.items = []`。

   之后用 `cli.py` 加了数据，**但内存里那个 `t` 不知道文件变了**。

   **这就是"内存和硬盘不同步"。**

   修法：在接口里加 `t.load()` —— 每次请求前重新读文件。

5. **接口"说谎"了** —— 删 `/todos/99`（不存在的序号），
   返回的却是 `{"message": "已删除"}`，而数据一条没少。

   **原因**：`TodoList.remove` 越界时只 `print` 一句，
   **不报错、也不告诉调用者失败了**。接口拿不到结果，只能笼统说"已删除"。

   修法：让 `remove` 返回 `True` / `False`，接口根据返回值说不同的话。

6. **`new.content` 为什么不是 `new`？**

   因为 `new` 是个**对象**（包裹），不是字符串。
   `new.content` 才是那个字符串。

   （不拆开会报 `AttributeError: 'NewTodo' object has no attribute 'strip'`
   —— 因为 `TodoList.add` 里用了 `.strip()`，只有字符串才有。）

7. **`content` 这个名字是哪来的？**

   **自己在 `class NewTodo` 里写的**：

   ```python
   class NewTodo(BaseModel):
       content: str
   ```

   换成 `text: str`，"请求体里必须有 text""`new.text` 才能取"全都跟着变。

   **和 10/3 的 `Student` 类是同一件事**：定义了属性 → 用点号取。

## 今天最重要的三个收获

### 一、`api.py` 分两个阶段

**阶段一：启动的时候**（读一遍文件、只执行一部分）

```
第 1、2 行  拿工具箱                ← 执行
第 3 行     app = FastAPI()         ← 执行（造一个空的服务器）
第 5 行     @app.get("/")           ← 执行（往服务器里登记一条路由）
第 6、7 行  def read_root(): ...    ← 只是"定义"，不执行
```

**读到文件末尾，服务器上有了几条登记**：

```
地址 "/"       → read_root
地址 "/todos"  → list_todos
```

**然后 uvicorn 说 "Application startup complete"，卡在那儿等。**

**阶段二：有人访问的时候**

浏览器访问 → uvicorn 查登记表 → **调用对应的函数** → 函数体才执行 → 返回结果

**验证方法（做过的实验）**：在函数里加一行 `print`
- 存盘重启时：**print 不出现**（只是重新登记）
- 浏览器刷新时：**print 出现**（函数被真的调用了）

**每刷一次，多一行。**

### 二、内存和硬盘会不同步

数据和代码不一样：**代码是只读的，数据是可变的**。

`t = TodoList()` 拿到的是启动那一刻的**快照**。
之后硬盘上的 `todo.json` 变了，**内存里的对象不会自己更新**。

**真实系统里，"数据放在哪儿"是核心设计决策**：

| 放哪儿 | 好处 | 坏处 |
|---|---|---|
| 内存 | 快 | **会过期**、多进程不共享 |
| 文件 / 数据库 | 每个请求都拿到最新的 | 慢一点 |

**大多数真实系统选数据库** —— 因为"数据只有一份权威来源"比快慢重要得多。

（后面还会遇到很多次，换了名字而已：缓存穿透、缓存击穿、Redis 和数据库不一致……）

### 三、`print` 给人看，`return` 给程序看

原来 `remove` 越界时只 `print("请输入有效数字")`。

- 在 `cli.py` 里：**没问题**——打印出来，用户能看见
- 在 `api.py` 里：**出问题**——**接口看不见屏幕，只能看返回值**

**所以一旦方法要被"别的程序"调用，就必须有返回值。**

**这是"能被复用的代码"和"只能自己跑的脚本"的分界线。**

（和 10/3 那次一样：`is_pass` 最初写成 `print("及格")`，应该 `return True/False`。）

## 今天完成的三层结构

```
入口层   cli.py（命令行）  +  api.py（网页）
            ↓        ↓
逻辑层   TodoList 类（规则都在这里）
            ↓
存储层   todo.json
```

**三个入口接口**：

| 地址 | 方式 | 干什么 |
|---|---|---|
| `/` | GET | 测试用 |
| `/todos` | GET | 列出所有待办 |
| `/todos` | POST | 添加一条 |
| `/todos/{index}` | DELETE | 删除第 index 条 |

**验证过的关键事实**：用网页加的待办，`cli.py` 里能看见——
**两个入口，一份数据。**
