## 今天学了

### 异常处理

- `try / except`：试着做，出错了不崩
- 常见异常类型：`ValueError` / `IndexError` / `KeyError` / `FileNotFoundError` / `ZeroDivisionError`
- **"重试直到输入正确"的模式**：`while True: try: ... break; except ValueError: ...`
- `except` 要写清楚类型，**不要写裸的 `except:`**

### 面向对象（上）

- 类与对象：**类是图纸，对象是按图纸造出来的实物**
- `__init__`：造对象时自动执行，用来装初始数据
- `self`：**"这个对象自己"**，`s1.say_hello()` 时 Python 自动把 `s1` 塞进 `self`
- **修改属性**：`self.balance = self.balance + amount`
- 属性 vs 方法里的局部变量：**属性挂在对象上会一直存在，局部变量方法一结束就没了**

## 卡在哪

1. **`guess1.py` 的三层嵌套，`break` 跳错层（踩了三次）。**

   - 第一次：把整个游戏逻辑塞进 `try` 的循环里 → 输入成功 `break` 直接跳出，游戏逻辑不执行

   **修法：删掉三个多余的 `break`，把游戏部分整体右移 4 格。**

   **记住这条：`break` / `continue` / 变量作用域，全都由缩进决定。**

2. **`withdraw` 的顺序反了——"先扣钱，再判断"。**

   ```
   取 9999 → 打印"当前余额不足"
             但对象里的余额被扣成了 -9199
   ```

   **提示看着是对的，数据已经被改坏了。**

   **原则：先确认操作能不能做，再做。** 写任何"修改数据"的操作都是这个顺序。

   （对照：`todo.py` 里删除是先判断序号合法才 `pop`——那里我做对了。）

3. **`show_balance(self, balance)` 多了个参数。**

   余额本来就在对象里，不需要外面喂。

   **判断标准**：外面传进来的（取多少钱）→ 做参数；**这个对象自己的**（余额）→ 用 `self.balance`。

4. **`18_class.py` 和主程序里反复忘括号。**

   ```python

   s1.say_hello()           # 对：加括号才是调用
   ```

   **这是第四次踩**（9/27 的 `f.read`、9/28 的 `print(print)`、今天的 `s1.say_hello`、`s1.deposit`）。

## 今天最重要的三个收获

### 一、`try/except` 只能接住"会抛异常的错误"

| 情况 | 会抛异常吗 | 用什么解决 |
|---|---|---|
| `int("abc")` | **会**（ValueError） | `try / except` |
| 难度输入不认识的值 | **不会** | `if / else` + `while` |

**"用户输了一个合法但不认识的值"不叫错误，叫逻辑分支没覆盖到。**

新手常犯的错是：什么都想用 `try/except` 包起来。但它是用来处理"意外"的，
不是用来处理"预期内的其他选项"的。

### 二、"提示对了"不等于"数据对了"

`withdraw` 那个 bug 好在：**屏幕上打印的东西完全正确**，只有对象内部的数据是坏的。

这类问题只能靠"去检查真实状态"发现，不能靠"看输出像不像对的"。

（和 9/30 那条一样：修好代码 ≠ 修好数据；也和"报错是好事"那条一脉相承。）

### 三、属性和局部变量的区别：谁能"记住"变化

```
用属性：加三次之后 → 3        ← 记住了
用局部变量：每次都打印 → 1     ← 记不住
```

**属性挂在对象上，只要对象还在就一直存在；局部变量方法一结束就消失。**

这也解释了为什么对象能"有状态"——`BankAccount` 的余额会随着存取变化，
因为它是属性，不是临时变量。
